## AI boundary

The product has four internal structured AI stages: persona inference, scenario selection, fact extraction, and explanation. Deterministic code owns scoring/classification. The opt-in test:ai-live command makes one potentially billable synthetic persona inference. It is connectivity/schema evidence only, not validation of five prompt types or production accuracy.

## Operations boundary

- Vercel Cron invokes the production `CRON_SECRET`-protected nightly route for retention, audit verification, and conformance. The optional in-process timer is a single-owner long-lived-host fallback; there is no Redis/BullMQ/Agenda queue or report-cache job.
- Assessment retention currently enforces closed-assessment handling. Evidence/dataset-history/per-object enforcement and external audit cold storage remain open.
- Audit archive export is bounded and manifested, but external immutable custody/retrieval is not configured by the repository.
- DR status stores operator-attested timestamps/outcome/reference. It does not query Atlas or prove backup/PITR.
- Sensitive values, result messages and reconstruction answer/fact values are masked in responses with audited privileged unmasking; there is no field-encryption middleware.
- There is no controller layer, SSE/EventSource contract, scenario factSchema, or second audit database in the implementation.
